# 安居有数前端

**Dream Defined. Living Refined.**

三套可以完整操作的家装需求协作前端，采用不同页面结构与视觉语言。需求共创已共用真实 AI 的表达、拆分、追问和确认模块；商家协作仍是本地规则与模拟公司。原来的 `mingma-mvp` 保留，此工程独立运行。

## 先从这里看

当前开发预览入口为 `http://127.0.0.1:5188/`。默认打开澄境。其他两套设计和截图作为历史参考。

| 版本            | 页面组织                                               | 适合先看什么                                               |
| --------------- | ------------------------------------------------------ | ---------------------------------------------------------- |
| 雾屿 Atmosphere | 自然摄影、烟色玻璃、生活便签、模型工作纸、悬浮导航     | 最接近参考图的自然光影和磨砂氛围，可用生活便签进入需求澄清 |
| 澄境 Lucid      | 顶部工作导航、中央房间画布、左右项目简报和区域需求抽屉 | 连续操作与空间需求联动，适合比较信息清晰度                 |
| 筑序 Atelier    | 建筑方案册、章节导航、纸面档案、双栏访谈与证据批注     | 团队展示与方案逐项审阅，适合比较文档式阅读体验             |

每版有项目概览、空间选择、需求共创、我的需求、方案比对、商家工作区、空间预览和确认记录，共 8 个功能页面。“我的需求”统一展示清单、派生待确认、项目背景和只读旧维度记录，不再提供独立评分表；旧 `#dimensions` 跳转到 `#requirements`。澄境的访谈、项目和商家草稿仅保留在本轮，刷新即清空。从 `#clarify` 进入 AI 共创。

「开始硬装规划」打开第二页 `#planning`，默认抬升卫生间，浴室柜与旧地砖热点定位侧栏条目。侧栏优先显示当前房间的实际需求，暂无记录时提供标注的演示清单。进入区域规划时预选当前房间，演示条目不自动写入需求。原「空间预览」继续用于查看方案和演示管线。

## 在其他电脑运行源码

使用 Node.js 24，与仓库根目录 `.nvmrc` 和持续集成保持一致。在当前 `mingma-lab` 目录执行：

```sh
npm ci
npm run dev
```

打开终端显示的地址。默认端口为 5188，仅绑定本机。停止服务使用 Ctrl+C。真实需求共创还需按 [AI 服务说明](../mingma-api/README.md)启动 5199 服务；Vite 已将 `/api` 代理到该端口，可通过 `MINGMA_API_URL` 指定测试服务地址。浏览器不配置模型密钥。

```sh
npm run build
npm run preview
```

构建结果在 `dist/`，静态站点提供澄境根入口和旧澄境地址跳转。生产预览前应先停止占用5188端口的开发服务，或指定其他端口。独立静态站点或 ZIP 不包含 AI 服务；真实共创需要同源 `/api` 转发。本机部署可使用项目根目录的启动脚本，详见[部署说明](../docs/local-deployment.md)。

## 快速验收

1. 从澄境进入需求共创，输入生活化表达并选择相关区域。
2. 点击 AI 梳理，检查复述、需求来源和每批最多两道问题；尝试多选、自由补充或暂缓。
3. 查看草稿中的全局、区域、公共项和待确认视图；同一待确认项目不应被重复计入。
4. 手动修改描述、归属或重要程度，采纳需要的建议，逐条勾选已核对；未知尺寸保持待测。
5. 有必须项冲突时先处理或暂缓。已有未发布草稿时，明确确认替换后采用。
6. 在“我的需求”查看关联待办，补充并保存项目背景，再主动发布 R1；检查原快照和待办没有被覆盖。
7. 修改回答并重新整理，检查受影响的确认状态需要重做，旧 R1 仍保留。
8. 导出访谈 Markdown/JSON，刷新检查本机保存；检查旧维度链接进入“我的需求”，历史记录可读，并在手机宽度检查表单、导航和错误恢复。

旧商家闭环仍可通过首页“完整演示”单独验收：查看木序设计的洗碗机配套缺口和栖居营造的开放格冲突，反馈、修订并选定方案。AI 生成的自定义需求不自动适用这套演示规则，应保留人工核对。载入完整演示会替换本机项目，先导出需要保留的内容。

同一局域网中的设备可直接使用 AI 需求共创，无需填写访问码。其他远端 AI 接口仍关闭，DeepSeek 密钥只保存在服务端，浏览器不持有该密钥。

首次进入为空项目是正常状态。验收过程中生成的内容只在本轮页面内有效；源码和静态包不包含浏览器中的项目填写结果。可通过“导出项目”保存自己的记录。

## 验证范围

本轮整合检查覆盖背景迁移与唯一来源、已答信息复用、待确认派生视图、旧路由兼容、旧记录导出和发布快照；实际页面、测试数量及部署结果见[整合验证记录](../docs/requirements-unification-verification.json)。

前一轮需求获取的 56 项前端测试、48 项 API 测试、39 项依赖模拟和 21 个 Postman 断言保留在[当时的验证记录](../docs/intake-release-verification.json)。

以下是保留的旧版本验收范围，不代替新需求页面的验证：

- 三版均通过 TypeScript 检查并成功构建。
- 每版的领域规则有14项测试，覆盖条件需求、未知回答、冲突、证据缺失、自定义需求、不可变修订与CSV边界。
- 每版主流程14项浏览器断言，覆盖需求澄清、发布、两商家、证据、反馈、修订、选定、版本失效及量表依据。
- 每版空间交互10项断言，覆盖三维投影、键盘旋转、俯视、房间联动、资料源隔离、线路图层和墙体。
- 每版额外15项边界检查，覆盖单商家提交、缺席商家证据、R2待处理筛选、逐商家选定、演示清理旧量表、草稿恢复。
- 展厅的版本切换、8项验收清单、状态隔离及三张手机预览均已检查。
- 1440px桌面、390px手机布局和关键功能页已截图检查；原始验收截图本地留存，仓库中的实际页面预览位于 `public/previews/`。

浏览器验证脚本会重置测试浏览器中对应版本的数据，请只在隔离的测试浏览器中使用。`scripts/browser-edges.js` 会自动根据当前版本路径选择其存储键。业务规则测试可直接执行 `npm test`。

## 修复的实际边界问题

缺席商家不再出现无效证据链接；旧需求版本的方案始终出现在待处理列表；一家方案过期不会阻止选择另一家当前方案；首页不将历史选择误报为新需求的已完成；载入完整演示会清理旧量表依据；示例只补充缺席商家，不覆盖已经提交的方案。

历史验收中，解压后的静态体验包也通过了同样的主流程、空间和边界检查，字体与图片均从包内加载。带日期的摘要见 [`review/verification.json`](review/verification.json)；原始截图与静态检查日志本地留存，不纳入仓库。当前提交的自动测试和构建结果以 GitHub Actions 为准，浏览器交互与视觉检查需要单独执行。

## 当前能力边界

这是前端 MVP 与独立 AI 服务的组合。新需求共创调用 DeepSeek；失败、取消或超时时保留输入，不会静默改成演示答案。最终范围、建议采纳和发布均由用户操作。商家身份及方案核对界面仍用于模拟，不构成真实商家账户或后台权限机制。方案导入支持结构化表单和 CSV，未实现任意 PDF/扫描件识别或云端项目数据库。

空间模型使用三维顶点投影的SVG，可旋转、缩放、点选房间与管线，不依赖WebGL。户型面积和线路是演示资料，不能作为施工图。商家没有提供空间数据时不会沿用演示线路。报价、价格排行、交易与付款不在本次范围内。

## 素材与字体

三张室内/材质图使用内建 imagegen 生成，用作视觉素材，不代表真实商家案例。WebP、原始PNG、完整提示词和校验值均保存在 `public/assets/`，详情见 `manifest.json`。参考图只用于视觉方向，没有复制其人物、应用名称或界面文字。

Atelier 的 Noto Serif SC 界面字体子集已保存在 `public/fonts/`，附 SIL Open Font License 1.1。其他版本采用系统字体后备，运行不依赖在线字体服务。


每个版本内的 `src/main.ts` 定义页面与交互并挂载共享 intake 模块，`src/domain.ts` 保留旧方案规则，`src/dimensions.ts` 保留旧记录名称和商家协作引导定义，不再生成独立量表页面。`shared/requirements-hub.ts` 负责项目背景迁移、待确认派生及旧记录展示。雾屿和澄境使用 `src/glass-model.ts` 绘制可交互户型，筑序使用 `src/atelier-model.ts`。户型上传建模仍为[待实现设计](../docs/floorplan-model-design.md)。各自 README、PRODUCT、DESIGN 说明该版本的结构与视觉取舍。
