# 安居有数 · 空间工作室

这一版以清楚的空间协作为中心。进入首页后，先看项目简报与下一步，再通过「开始硬装规划」进入空间选择页；顶部工作标签连接完整流程。视觉采用通透白色、冰蓝、光学磨砂与柔和窗光。

## 入口

开发服务启动后访问 `/versions/lucid/index.html`。每页右上角可返回设计展厅，手机显示返回箭头并提供无障碍名称。

## 推荐验收

1. 开始需求共创，填写生活化表达并选择相关区域，检查 AI 复述与拆分。
2. 回答动态选择题、自由补充或暂缓，再查看四组草稿及来源、标准和核实责任人。
3. 编辑条目、采纳需要的建议并逐项确认。处理必须项冲突后明确采用，再在“我的需求”发布。
4. 修改回答并重新整理，检查旧快照保留、受影响条目需要重新确认。
5. 刷新恢复访谈，导出 Markdown 或 JSON，检查手机布局和请求失败恢复。
6. 用首页“完整演示”另行查看模拟商家的遗漏、冲突、反馈、修订和选择；真实 AI 条目不自动套用旧规则。
7. 在“我的需求”查看关联待办、保存项目背景并回看只读旧记录；检查背景进入后续 AI、旧路由兼容和历史版本保持。

本版有 8 个功能页面（含商家工作区）。“我的需求”统一清单、派生待确认、项目背景和只读旧维度记录；导航不再显示独立维度页，旧 `#dimensions` 进入 `#requirements`。商家九维仅在商家工作区引导回应，原记录不自动属于某家企业。

首页也提供完整案例快捷入口。真实数据未输入时，不显示虚构的AI完成率或商家排名。

## 范围

需求共创通过同源 `/api/ai/intake` 调用 DeepSeek，使用共享界面和状态模块；商家比对仍使用本地规则与模拟公司。静态 ZIP 不包含后端，独立运行时需配置同源 API；接口失败不静默返回演示答案。同一局域网内可直接使用需求共创，无需访问码，模型密钥保留在服务端。

数据保存在本机浏览器，使用独立 `mingma-lucid-*` 命名空间，访谈键为 `mingma-lucid-intake-v2`。不存在真实商家账户或云同步，三版之间也不共享填写内容。户型、尺寸和路线仍为示意，上传建模尚未实现；价格不参与判断。
