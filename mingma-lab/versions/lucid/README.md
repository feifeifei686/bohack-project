# 安居有数 · 空间工作室

这一版以清楚的空间协作为中心。首页约 7 秒完成三维住宅搭建，镜头扫过约 52°；通过「开始硬装规划」进入空间选择时，标题放大退出，房屋转为俯视并连续缩入图纸。顶部工作标签连接完整流程。品牌 slogan 为「Dream Defined. Living Refined.」，视觉采用奶油白、雾紫、冰蓝与磨砂玻璃。

## 入口

开发服务启动后访问根路径 `/`；旧 `/versions/lucid/index.html` 会跳转到根入口。首页导航及项目工作台菜单连接各功能页。

## 推荐验收

1. 从首页进入空间选择，查看演示图纸并生成立体户型，或上传图片后手工标注房间；选区域进入共创，填写生活化表达，检查 AI 复述与拆分。
2. 回答动态选择题、自由补充或暂缓，再查看四组草稿及来源、标准和核实责任人。
3. 编辑条目、采纳需要的建议并逐项确认。处理必须项冲突后明确采用，再在“我的需求”发布。
4. 修改回答并重新整理，检查旧快照保留、受影响条目需要重新确认。
5. 导出 Markdown 或 JSON，再刷新检查本轮访谈已清空；检查手机布局和请求失败时输入保留。
6. 用首页“完整演示”另行查看模拟商家的遗漏、冲突、反馈、修订和选择；真实 AI 条目不自动套用旧规则。
7. 在“我的需求”查看关联待办、保存项目背景并回看只读旧记录；检查背景进入后续 AI、旧路由兼容和历史版本保持。
8. 打开“空间预览”，选择六个工程层，调整展开程度，测试合拢、单层查看、旋转与缩放，再切回“房间与线路”验证原控件。

本版有 8 个功能页面（含商家工作区）。“我的需求”统一清单、派生待确认、项目背景和只读旧维度记录；导航不再显示独立维度页，旧 `#dimensions` 进入 `#requirements`。商家九维仅在商家工作区引导回应，原记录不自动属于某家企业。

首页也提供完整案例快捷入口。真实数据未输入时，不显示虚构的AI完成率或商家排名。

## 范围

需求共创通过同源 `/api/ai/intake` 调用 DeepSeek，使用共享界面和状态模块；商家比对仍使用本地规则与模拟公司。静态 ZIP 不包含后端，独立运行时需配置同源 API；接口失败不静默返回演示答案。同一局域网内可直接使用需求共创，无需访问码，模型密钥保留在服务端。

项目、访谈、商家草稿和上传图纸只保留在当前页面内存，刷新后清空；旧 `mingma-lucid-*` 存储在入口初始化时清理。不存在真实商家账户或云同步。上传图片需要手工标注矩形房间，自动识别和尺寸校准尚未实现。首页与工程分层使用 Three.js，旧房间模式使用 SVG；工程分层复用首页住宅，不读取上传图纸或商家方案。户型、尺寸与路线均为示意，价格不参与判断。
