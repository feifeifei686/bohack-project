# 安居有数 · 空间工作室

品牌名称为「安居有数」，slogan 为「Dream Defined. Living Refined.」。面向希望逐项把需求说清楚的业主。首页用奶油白、浅香槟、雾紫与冰蓝形成明亮弥散氛围；工作页保持安静的玻璃表面；空间选择保留用户参考的左右布局，随后按用户要求统一为奶油白与雾紫的工作页。

## 组成

- 首页首屏展示真实三维住宅，地面、墙体、门窗、家具依次搭建，最后以淡紫色发光走线收尾，搭建全程约7秒，之后保留缓慢俯仰、视角微动和沿路径流动的拖尾。可切换完整空间和建筑结构，画面不放进度条、时间或播放控件。边缘放置磨砂玻璃导航与「开始硬装规划」，项目工作台菜单保留全部路由、导出和演示说明。下方先展示生活想法、需求清单和方案差异的厨房成果案例，再展示规划流程、项目状态和协作轨迹；案例明确标为演示。已有草稿时主入口变为“继续我的项目”，并显示保存时间。第二页「空间选择」先呈现左侧标题及生成/上传/下载操作、右侧五区平面图。生成后才进入沙盘和区域硬装清单。
- 共创页采用四步问卷：表达想法、补充细节、逐条确认、提交问卷。每次呈现一个问题或一条需求，专业回应条件、原话和编辑区默认折叠。桌面右侧保留户型定位，手机放在问卷之后。
- 需求清单保留草稿、优先级、版本发布与逐项编辑；工具条与记录保持同一视觉层级。
- 方案对比先展示必须项冲突、遗漏与追问建议，点击可定位到对应原文；下方继续以同一需求编号逐项比较，保留原文证据、问题反馈和旧版失效提示。
- 商家工作区使用需求说明与回应表单对照布局，提交操作条保持可见。
- 空间页默认“我的户型与需求”，沿用空间选择中的当前模型与房间名称，按房间查看对应需求；“当前户型 · 墙体调整”保留同一模型。六层工程分解收于“了解装修构成”，结构与拆改、水电管线、防水与铺装、吊顶与木作、柜体与固装、家具与居住均明确属于独立教学示意，支持原有合拢、展开、选择、单层查看、旋转与缩放。“房间与线路示意”同样单独标示来源，缺少商家空间数据时不展示样例管线。
- 我的需求统一展示清单、派生待办和项目背景；背景只填写一次并带入共创，旧维度记录以只读档案保留。
- 确认记录保存被选定的需求与方案快照，当前需求改变后明确指出历史选择状态。

## 交互细节

手机首页额外提供靠前的主行动。横向项目导航在进入页面时自动定位当前标签；表格在自身容器内滚动，不撑宽页面。房间、线路和视图均有文字操作作为替代。关键操作有键盘焦点、触控目标和明确的保存状态。

## 代码与资产

Tailwind v4 工具类配合组件CSS。`src/main.ts` 保存页面模板和客户端交互；`src/style.css` 定义 Lucid 外壳、空间工作台和各任务页面的细节；`workspace-glass.css` 保留共享任务组件基础；`glass-model.ts` 提供原房间与线路模式的 SVG 投影。`engineering-data.ts` 定义六层说明，`engineering-ui.ts` 连接控件与降级说明，`engineering-view.ts` 复用首页几何并创建工程层，`engineering.css` 定义分层布局。域规则 `domain.ts` 未改变。

室内素材使用设计展厅共享的 `/assets/lucid.webp`，生成出处及提示词保存在展厅 `public/assets/manifest.json` 与 `lucid.prompt.txt`。素材只表达氛围，不表示真实商家提供的方案。

首页由 `home-architecture.ts` 构建真实 Three.js 几何，`home-builder.ts` 使用同一场景、相机与时钟完成7秒搭建。`home-light-routes.ts` 在5.6秒起沿底盘及公共通道渐绘发光走线，7秒后继续缓慢流动。走线为视觉示意。`home-scene.ts` 连接图层切换、导航与生命周期，离屏冻结进度，减少动态偏好下直接展示完整模型。`home.css` 限定首页视觉，主色为 `#383541`、辅助色为 `#5c557e`。不支持 WebGL 时显示用户提供的 `public/assets/home/residence.webp` 参考图及加载说明，来源记录在 `sources.json`。


## 本轮视觉实现（2026-11-14）

首页相机在原有适配基础上放大12%，材质使用室内环境反射、暖色主光和冰蓝/雾紫补光；同一时钟驱动搭建、视角与流光。帧率上限30fps，离屏/后台停止，减少动态偏好下直接呈现完整静态模型。

`home.css` 使用 `public/assets/home/luminous-atmosphere.webp` 作为缓慢平移缩放的背景。素材由内建 image_gen 生成，原始提示词在同目录 `luminous-atmosphere.prompt.txt`，来源与 SHA-256 在 `sources.json`。该素材只表达氛围，不能作为真实房屋/商家方案。

`luminous-workspace.css` 统一任务页、弹窗和通知的颜色与字体。`planning-entry.css` 保留左右分区参考，并与后续页面共用顶部导航、字体和表面材质；共享模块通过 editorial 选项隔离其他历史版本。上传图纸可通过 AI 识别房间、墙线、门窗和可见家具，也可手工校对与标注；识别结果仍需人工核实，生成结果为概念模型，比例尚未校准。

需求共创以问卷呈现，继续复用现有 AI 接口、逐条确认规则和主动发布流程。

首页进入空间选择时，完整房屋在约1.8秒内抬升到无人机俯瞰视角，周围UI放大、模糊淡出，再衔接工作页。无平板。提前点击会先收拢搭建阶段；重复点击被锁定；离开页面取消回调；减少动态偏好直接进入并短暂淡入。

俯瞰结束时保留当前渲染画面，跨路由连续移入右侧图纸的实际边界；约0.85秒完成位置与尺度归位，再用0.45秒将房屋图像交叠过渡到平面线稿。过渡期间不显示空白画面，手机在覆盖层下将目标图纸定位到视口。改变窗口大小或离开页面会清理过渡层并恢复操作。

首页住宅与五区演示图纸的内部布局不同，转场对齐外轮廓并交叠，不代表同一几何模型的平立面转换。已有生成模型时再次进入会保留当前阶段；键盘进入后恢复规划标题焦点。工程页 WebGL 不可用时仍可选择层级阅读说明，依赖模型的控件停用，并保留旧 SVG 模式入口。

搭建节奏：地面约0.8秒成形，墙体约1.6秒升起，门窗至2.7秒，家具分批缓慢出现至6.2秒，细节至6.8秒，走线在7秒前完成。镜头水平扫过约52°、俯仰变化约18°，采用先快后慢的减速曲线；完成后保留更明显的缓慢环绕。

进入规划时，首页主标题与说明围绕视口中心向外放大，前段保持不透明，越过屏幕边缘后淡出（1.25秒、最大8倍）；其他导航与按钮同步放大退出。文字层置于过渡背景之上，避免提前被背景盖住；减少动态模式不放大。

首页背景通过 `home-atmosphere.ts` 对已有图片进行实时柔波偏移与缓慢漂移，幅度约为初版的1.5倍，最多20帧/秒。只在首页创建，离屏/后台暂停，进入规划前冻结，退出首页销毁；减少动态时使用静态底图。跨页覆盖层和其他页面不使用此动效。

## 问卷与项目进度（2026-11-14）

项目导航显示六个顺序步骤、当前状态、已完成标记和后续锁定。选定空间后解锁共创，采用问卷后解锁需求清单，发布后解锁方案对比，查看方案后解锁空间预览，确认选择后解锁记录。返回早期步骤不撤销已取得的访问权限；直接输入未解锁路由也会回到当前可用步骤。刷新后从此浏览器、此地址的本地草稿恢复进度；未解锁入口保留可理解的前置说明，并引导到当前可用步骤。

问卷保留自由表达与 AI 动态追问，提供本轮题数、上一题和四阶段进度。确认页一次只看一条需求；建议须明确采纳，未解决的必要业主决策提供补充回答或暂不纳入。最后集中预览并提交，不把现场待测、专业复核或未决事项当成已核实。项目背景与补充档案收起在“我的需求”的折叠区。

需求发布后进入“商家正在制作”演示状态。木序设计和栖居营造各有一份可立即展开的预制方案，使用现有风格参考图，按已发布需求编号生成演示回应；不是实际商家交付。点击后可逐项对照、查看空间和确认选择，重复查看不会重复生成版本。

## 风险评估（2026-11-14）

导航位于方案对比之后，在生成需求后即可访问，保持六步主流程的回看权限。顶部选择评估对象并给出当前操作结论；桌面左侧为八维筛选列表，右侧为按证据展开的问题和处理安排。手机维度采用两列，问题单列展开。沿用奶油白、雾紫及既有文字层级，风险使用文字状态与低饱和底色共同表达。处理记录内联填写，不用勾选消除风险；旧结果过期时显示重新评估。


## 墙体拆除视图（2026-11-14）

生成后的立体户型提供“墙体拆除 · 整体与分部展开”入口；空间预览也可切换“墙体拆除”。两处共用项目草稿状态与当前户型墙线，识别户型保留门窗开口，演示与手工标注显示相应来源。

左侧轴测模型用原位虚线和连接线呈现墙体移出关系，支持整体、按房间、单段墙三种展开，滑杆控制程度，合拢复原恢复拆前显示。右侧可定位房间、点选编号墙段、标记拟拆除及预览拆后；共用墙可由相邻房间定位。键盘可选择模型墙段，数值按钮作为小屏替代入口。保留奶油白、雾紫操作色，拟拆除使用暖陶色并配文字标识。

展开仅在变化期间绘制，减少动态效果时直接显示目标位置。拆除标记不改写原始户型，不自动发布需求或判断可拆性；状态随当前模型保存在 IndexedDB，并写入完整项目 JSON；换图或修改模型后按当前墙线重新建立状态。


墙体视图增加“承重墙 / 非承重墙 / 待核实”三类人工标注。初始均为待核实，不从识别墙线、粗细或示例布局推定承重。模型墙面、编号标签、图例与列表同步显示性质；右侧保留人工标注来源与选填依据备注。承重标注会取消该墙的拟拆除状态，并在按钮和事件层禁止重新标记拆除；非承重标注不等于已确认可拆。拆除意向采用独立虚线描边，清空拆除标记不清除性质标注。备注按普通文本显示，标注随项目自动保存，并进入完整项目 JSON；保存不改变其人工标注、待专业核实的性质。


## 工作效率与项目续接（2026-11-14）

工作页缩短顶栏、导航、项目进度和大标题的间距，规划入口不再保留撑高首屏的最小高度；输入和主操作更靠前。手机导航仍可横向滚动，主要触控目标保持至少44px。首页示意说明采用至少12px文字，完整案例入口保留足够对比。

共创表达示例优先依据当前单一区域：卫生间、厨房、卧室、客厅、玄关、走道与阳台各有生活化示例，多空间使用全屋示例。已有范围收起在“涉及区域 / 调整范围”中，可展开修改。输入框初始为四行，专业信息与逐条采纳仍由用户确认，不改变 AI 请求和发布规则。

保存状态在项目抬头、问卷和页脚呈现，成功后显示时间；进行中、失败和恢复异常使用具体文案。项目通过 IndexedDB 自动保存访谈、图纸、模型、墙体状态、需求与方案历史，刷新后恢复。草稿只属于同一浏览器和同一网站地址，不跨设备或不同主机地址同步。读取或校验失败时不覆盖原记录，可重试读取或导出原始记录；多页面发生版本冲突时保护较新的草稿。清除草稿必须确认，并提示先导出。

“导出项目”提供沟通报告预览、浏览器打印 / 保存为 PDF，以及完整项目 JSON 备份。报告以适合阅读和打印的排版汇总户型、需求、方案差异与证据、待确认和记录，明确区分未发布修改与已发布核对基准。JSON 保留访谈、原图、墙体标注及完整项目历史；目前没有 JSON 导入入口。
