# C 版 筑序 Atelier

访问根设计展厅后选择 C，或打开 `http://127.0.0.1:5188/versions/atelier/index.html`。

这是一版可操作的建筑方案册。桌面采用细目录、宽幅厨房摄影、项目摘要与双栏轴测图；功能页采用访谈记录、需求档案、证据批注与印刷式对照表。手机版本保留横向章节导航及完整工作流程。

## 页面与验收入口

| 页面 | 地址片段 | 主要操作 |
| --- | --- | --- |
| 项目总览 | #overview | 开始访谈、完整示例、空间选择、重置 |
| 生活访谈 | #clarify | AI 拆分、动态追问、四组草稿、编辑与逐项确认 |
| 我的需求 | #requirements | 当前清单、派生待确认、三项背景、只读旧记录、发布与历史版本 |
| 方案审阅 | #compare | 两商家比较、证据、反馈与选择 |
| 商家修订 | #vendor | 承接协作引导、CSV模板与导入、手动编辑、修订 |
| 空间图纸 | #space | 旋转、俯视、房间与管线图层 |
| 确认归档 | #records | 选择快照、未决项及操作记录 |

当前共有 8 个功能页面。原独立维度页已撤下；旧 `#dimensions` 链接会进入“我的需求”。

## 实现与数据

主模板在 `src/main.ts`，基础和首页样式在 `src/style.css`，功能页样式在 `src/workspace-atelier.css`。`src/atelier-model.ts` 使用三维顶点投影绘制可交互模型，不依赖WebGL。摄影引用根目录的 `/assets/atelier.webp`，为概念参考素材，不是实际商家方案。

访谈通过共享 `intake-ui.ts` 和 `intake-state.ts` 调用同源 `/api/ai/intake`。用户表达与区域选择后，AI 提供复述和每批最多两题；用户在四组草稿中编辑、采纳建议并逐项确认，明确采用后再进入原需求发布流程。已发布快照保留，标准和现场待办不会自动变成已确认事实。

“我的需求”的项目背景保存后自动随下一次 AI 访谈传入，共创中只读展示；修改背景会撤销旧确认并要求重新整理，发布快照保留当时背景。待办从原需求派生，旧量表仅供追溯和导出。

数据隔离键包括 `mingma-atelier-v1`、保留作历史的 `mingma-atelier-dimensions-v1`、`mingma-atelier-drafts-v1` 与 `mingma-atelier-intake-v2`。商家九维在商家工作区作为回应引导，未绑定企业的旧商家记录不冒充任何公司的承诺。项目仅存当前浏览器，没有真实企业发送或跨设备同步。商家核对仍使用本地规则和模拟身份；上传户型建模尚未实现。

真实访谈需要 AI 服务，静态体验 ZIP 不能独立完成模型调用。同一局域网内可直接使用需求共创，无需访问码，模型密钥保留在服务端；请求失败会保留输入和草稿，不静默换成演示数据。
