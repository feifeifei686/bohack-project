# 明码网页 MVP

以厨房改造为示例，完成需求澄清、需求版本发布、两家模拟商家的方案回应、规则核对、问题反馈、商家修订和用户选择。包含业主 10 项和商家 9 项需求维度量表。

界面使用 Tailwind CSS v4，通过 Vite 插件本地编译。HTML 模板位于 `src/main.ts`，统一配色、字体和移动端优先组件样式位于 `src/style.css` 和 `src/workspace-glass.css`。当前采用云白、冰蓝与轻暖环境光的光学玻璃界面。首页使用简约轴测户型插画、透明空间锚点和磨砂悬浮导航。材质由真实 backdrop-filter、半透明表面、细白高光及轻柔阴影构成。

## 运行

需要 Node.js 22.18 或更新版本。首次运行 `npm ci`，然后执行 `npm run dev -- --port 5180`，浏览器访问终端显示的地址。

`npm run build` 检查 TypeScript 并构建静态网页；`npm run preview -- --port 5180` 预览构建结果；`npm test` 执行需求生成、证据核对和 CSV 边界测试。

`npm run format` 整理 HTML 模板、样式及构建配置的代码格式。

## 体验顺序

1. 首页点击开始梳理需求，输入原始表达，回答五组选择题。
2. 编辑需求清单的重要程度或描述，发布 R1。
3. 方案比对载入演示商家，查看洗碗机配套遗漏和开放展示格冲突。
4. 生成反馈后进入商家工作区，手动修改或填入修订示例，提交新版本。
5. 通过证据原文与空间示意理解方案，选定时保留现场待办。
6. 需求维度量表可独立填写、评分与导出。3 分必须提供回答或确认依据；优先级单独保存。

首页也提供完整演示快捷入口。已有数据时会要求确认覆盖。

## 实际能力边界

- 未接入大模型。使用问题模板和明确标记的文本规则；用户自定义或编辑后的需求转人工核对，不直接声称已满足。
- 数据保存在当前浏览器 localStorage，没有后台账户、跨设备同步或真实商家通讯。商家身份仅用于模拟协作，不是权限安全机制。
- 提交支持表单与 CSV。CSV 表头为 `requirementId,commitment,text`；commitment 可取 yes、partial、no、unknown。资料解析和提交前均提供人工检查。
- 提供基于三维顶点投影的 SVG 简约轴测户型，支持轨道旋转、缩放、俯视、房间和管线选择，不依赖 WebGL。商家未提供空间数据时不显示独立样例线路。
- 所有户型尺寸和路线都是示例，不是施工图。价格不参与任何判断。
- 量表 0–3 只表示信息成熟度，不是满意度、方案评分或施工可行性结论。

## 数据和测试

项目、商家草稿和量表分别保存，导出项目 JSON 包含三者。重置会清除当前本机项目及量表。旧需求、方案和最终选择绑定的快照始终保留。

`tests/browser-flow.js` 是供 gstack browse eval 执行的浏览器流程测试。它会重置当前测试浏览器内本应用数据，仅在隔离测试浏览器运行。覆盖澄清、发布、对比、反馈、修订、选择、版本失效及量表证据校验。

## 后续接入

真实 LLM、后端数据库、商家账户、PDF 解析和专业知识审查属于后续工作。现有状态、版本和证据字段可用于定义后端接口，但本版没有实现这些服务。

`tests/browser-space.js` 检查空间模型的投影变化、房间联动、线路隔离及图层/墙体操作。
