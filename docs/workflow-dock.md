# 统一下一步与缺项定位

所有工作页（首页除外）共用屏幕底部的浮动操作栏：左侧显示当前任务、简短说明和保存提示，右侧放“上一步 / 下一步”。窄屏上下排列，正文和滚动定位保留操作栏占用的空间。

## 行为

- 未完成必要输入时，下一步保持可点击。点击后滚动到具体字段或选择区，展开相关折叠内容，移入焦点，执行约 1.8 秒的两次柔和强调，并显示文字说明。输入或修改后清除提示。
- 系统设置减少动态效果时，使用静态高亮和直接定位。屏幕阅读器通过焦点、`aria-describedby` 和状态文字获得同一说明。
- AI 请求或户型生成期间显示忙碌状态，防止重复提交；取消与重试仍保留在对应内容区。
- 户型生成、共创内部题目与条目、发布后的 Flash、方案和空间之间都复用这一操作位置。问卷原有前进/后退按钮、页面上重复的前进按钮及顶部重复说明收起。
- AI 建议显示“采纳建议，下一步”；发布仍经过确认弹窗和原有评估规则；方案选择只定位到用户需要选择的位置，不自动选商家。现场待测、未知区域等可保留信息不会新增强制门槛。
- 辅助风险页和商家页记住进入它们的主流程页面。商家说明缺失时定位具体文本框；风险事项不会因为填写处理安排而自动解除阻断。

## 实现位置

- `mingma-lab/versions/lucid/src/workflow-action.ts`：按当前真实状态决定下一步。
- `workflow-dock.ts` / `workflow-dock.css`：浮动栏、布局空间、缺项强调与焦点清理。
- `workflow-integration.css`：仅在 Lucid 新导航启用时收起重复控件，保留其他版本行为。
- `mingma-lab/shared/intake-ui.ts`：新增 `navigation / advance / previous`，复用原有共创校验和确认逻辑。
- `main.ts`：连接路由、规划、发布、评估和方案选择。

前端 128 项测试与生产构建通过。真实应用通过既有 Postman 模拟依赖进行浏览器联调：18 项断言覆盖户型生成、空白表达、未答题、上一步恢复、逐项确认、显式建议采纳、阻断条目、发布确认、Flash 跳转、未查看方案与主动选方案。额外检查了商家空白回应定位、确认选择后进入记录，以及从顶部导航进入风险页后返回来源页。

1440px 桌面、390px 与 320px 手机布局均已查看。320px 下无横向溢出，高亮输入框位于操作栏上方。减少动态效果完成代码检查；本轮浏览器未模拟系统偏好。机械样式检测无发现。
