# 提交后的 Flash 需求图谱

在“我的需求”确认发布后，先保存只读需求版本，再请求 `POST /api/ai/requirement-insight`。页面保留在第 3 步，呈现 Flash 二轮分析；用户可继续查看方案，也可返回清单。已有版本提供“查看需求图谱”入口。

## 展示口径

- 图谱节点来自提交时的需求。等待时的中心连线表示清单结构；实际需求关联只在 Flash 结果通过校验后出现。
- 关联分为配套、支持、取舍；每组关联都必须引用两端需求的原文。同一对条目最多一条关联，无依据时不补线。
- 表达清晰度 = 本轮判断表达清晰的条数 / 需求总数，四舍五入为整数百分比。它不是施工可行性、风险概率或满意度评分。
- 必须项沿用用户优先级。待确认数量按合并原有待办和本轮补充后去重计数。模型不能自行输出统计数字，服务器从有效条目计算，浏览器再次核对。
- 点击节点可查看简明结论、原文引用、待确认事项和相关需求。大清单的概览显示前 8 条，下方可以选择全部需求。

## 状态与版本

分析不会改写用户需求、替用户采纳建议或联系真实商家。失败时保留已发布版本，重试只重跑分析，不增加需求版本。离开页面不会强制跳回；切换分析版本或重置项目时取消旧请求，迟到响应不能写入新项目。结果附在对应发布快照中，随本机项目保存和 JSON 导出；修改草稿后查看旧结果会显示版本提示。刷新后可再次从清单打开已保存结果；未完成的分析可手动重试。
