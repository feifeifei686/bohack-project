# 演示与验收指南

推荐在独立浏览器或无真实数据的测试窗口操作。数据仅在当前页面内保留；「载入完整演示」和重置会改写该版本的本机记录。若已有填写内容，请先在确认记录中导出项目。

## 打开澄境

在 `mingma-lab` 运行 `npm ci`、`npm run dev`，打开 [澄境首页](http://127.0.0.1:5188/)。页面刷新后从空白演示开始。

## 完整演示路径

| 步骤 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 1. 表达需求 | 首页点「开始硬装规划」，选厨房并进入该区域规划，输入「厨房想好打理，预留洗碗机，保留现有布局和窗，不要开放展示格」 | 原始表达被保留，随后进入问题澄清 |
| 2. 回答问题 | 回答 AI 根据当前表达提出的问题，也可多选、补充或暂缓 | 得到按全局、区域、公共项整理的草稿；条数随输入变化，尺寸与接口未知项保留 |
| 3. 发布基准 | 查看需求描述与优先级，确认并发布 | 产生 R1；只有主动发布才成为方案核对基准 |
| 4. 比较商家 | 在方案比对载入演示商家 | 对 AI 生成的自定义需求，演示规则保留人工核对。要观察预设配套遗漏和柜体冲突，请使用首页“完整演示”样例 |
| 5. 查看依据 | 点击对应项目的原文依据 | 展示方案原文、缺口与下一步，不只是一个判断标签 |
| 6. 反馈修订 | 生成反馈，进入商家工作区；选对应商家，修改说明或填入修订示例，再提交 | 形成新的方案版本；重新检查已补充的文字说明，现场未知项继续保留 |
| 7. 用户选择 | 阅读当前方案与待办后选定 | 确认记录保存需求版本、方案版本及未决事项 |
| 8. 检查变更 | 修改需求并发布 R2，再返回方案比对 | 旧方案提示需按新基准核对，历史选择仍保留其 R1 快照 |

也可用首页完整演示快捷入口直接观察已有 R1 和商家回应，但答辩时建议至少手动演示一次「反馈 → 修订 → 重新核对」。

## 辅助功能验收

**我的需求：** 检查清单、派生待确认项、三项项目背景和只读历史填写都在同一页面。旧 `#dimensions` 链接应跳转到此页，不再显示评分表。空背景不能勾选已核对；修改文字应撤销旧核对。保存背景后，AI 共创应只读带入同一份内容；背景变化后需重新整理并采用 AI 草稿才能发布。商家的承接检查在商家工作区查看。

**空间选择：** 首页无沙盘。点「开始硬装规划」先查看内置演示图纸，再点「生成立体户型」观看墙体和家具升起。生成后默认卫生间抬升，墙体与地台一起移动；点浴室柜、旧地砖检查清单高亮。切换客厅后检查清单与房间按钮同步，进入 AI 规划时检查客厅已预选，返回后仍选客厅。

**共创户型小窗：** 从完整沙盘进入共创，户型缩至右上角并缓慢摆动；首次输入和提交时检查光效反馈。连续回答浴室柜和客厅地面问题，检查小窗随当前问题切换，返回空间选择可查看完整户型。

**空间预览：** 切换房间、拖动或使用键盘旋转、切换俯视、开关墙体和线路图层。对没有空间资料的商家，应看到资料缺口，不应显示属于独立演示户型的路线。

**单商家与草稿：** 只提交一家商家时，另一家保持未提交，不出现无效原文链接。切换商家或页面后，未提交草稿应能够恢复。

**版本隔离：** 一家商家针对 R2 提交新方案，另一家仍引用 R1；当前版本方案的选择资格应独立判断，旧版本方案仍保留待核对提示。


**响应式：** 检查 390px 手机宽度和桌面宽度。页面不应产生整体横向溢出，主按钮、导航、弹窗和表单需可操作；内部对照表或章节导航可按设计横向滚动。

## 向评委说明的边界

可以这样介绍当前成果：

> 我们先把用户需求固定成可追溯的基准，再让商家逐项回应，检查说明是否缺失或冲突。需求共创使用 AI 整理与追问；商家方案页面使用可解释的本地演示规则，自定义需求、现场条件和超出规则范围的内容保留人工确认。用户的最终决定会同时留下需求版本、方案版本和未决事项。

不要把规则核对描述为已经接入的大模型能力，不把「已回应」描述为施工验收通过，不把示例模型描述为真实施工图。自动学习与经验库在产品规划中，当前没有自行训练或更新规则的服务。
