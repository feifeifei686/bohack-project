# 演示与验收指南

使用独立测试浏览器或测试来源。项目会自动保存在当前浏览器的 IndexedDB；刷新不会清空。「完整演示」、重置和清除草稿会影响当前项目，已有内容请先导出。

## 启动

按[本机部署说明](local-deployment.md)启动，或在 `mingma-lab` 运行 `npm ci`、`npm run dev`，打开[澄境首页](http://127.0.0.1:5188/)。真实共创、图片识别和 Flash 分析还需要按 [API 指南](../mingma-api/README.md)启动服务。

首页「完整演示」可快速查看既有需求版本与模拟方案。要展示 AI 和多房间流程，使用下列路径；不要把完整演示结果当成现场生成的模型回答。

## 主流程

| 步骤 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 1. 选择空间 | 使用演示图纸，或上传 PNG、JPG、WebP 并校对识别结果；生成立体户型 | 房间可选择，上传模型保留来源说明；识别错误可校对或重试 |
| 2. 整理第一个房间 | 进入厨房，表达「想好打理，预留洗碗机，保留现有布局和窗」；回答追问并逐条确认 | 未知尺寸保留；AI 建议需要主动采纳，底栏引导下一步 |
| 3. 保存并切换 | 保存厨房需求，返回房间选择，再整理客厅；之后返回厨房 | 两个房间表达和问卷进度独立，保存一个房间不覆盖另一个 |
| 4. 查看总清单 | 查看各房间已保存需求，核对优先级、待确认事项和项目背景 | 未保存的房间修改仍在该房间草稿；总清单不会提前采用 |
| 5. 主动发布 | 提交并确认总清单 | 生成只读需求版本，进入 Flash 需求图谱；既有风险与确认门槛保留 |
| 6. 查看分析 | 选择图谱节点，检查结论、两端原文和待确认信息 | 表达清晰度不被描述为施工评分；失败时保留发布版本，重试不新增版本 |
| 7. 比较与修订 | 查看模拟商家回应、原文依据；生成反馈，在商家区修改并提交 | 方案引用需求版本，修订产生新方案版本；自定义需求保留人工核对 |
| 8. 确认与导出 | 阅读方案与未决事项后主动选定，预览报告并打印 / 保存 PDF | 记录需求、方案和评估快照；报告按 P1 必须、P2 偏好整理，可另下载完整 JSON |

预设厨房案例可展示配套遗漏与柜体冲突；AI 生成的自定义条目不应被旧案例规则自动判为通过。

## 关键验收

- **恢复与保存：** 填写两个房间后刷新同一来源，查看首页继续入口、保存时间、各房间草稿、总清单及上传图纸是否恢复。切换端口、主机或浏览器时数据独立；不要据此判断原记录丢失。保存异常应显示提示，不冒称已保存。
- **下一步与缺项：** 在表达空白、问题未答或商家回应缺失时点下一步，应定位具体位置、显示说明并转移焦点。AI 请求中避免重复提交；现场待测事项不会被强制改成已知。
- **版本隔离：** 发布 R1 后改草稿，旧图谱应注明版本；发布 R2 后仍引用 R1 的方案提示重新核对。失败重试不重复发布，旧选择记录保留当时快照。
- **背景与确认：** “我的需求”维护三项项目背景；文字改变撤销对应旧核对，下一次共创带入新背景。旧 `#dimensions` 链接进入需求页。填写风险处理安排不等于专业核验完成。
- **户型与墙体：** 上传图纸后检查房间 / 家具校对与需求定位；空结构图不应补出无依据家具。墙体默认为待核实，可手工标注并备注；标为承重后取消并禁用拆除意向。标注和拟拆除状态刷新后保留，不自动形成需求条目。
- **空间预览：** 默认查看当前户型与关联需求；另行切换六层工程或房间线路示意，检查来源说明，不把独立示意当成上传户型或商家施工方案。
- **报告：** 预览 P1 / P2、房间分组、原文与待确认责任方，打印时检查长条目、表头和分页。完整 JSON 为留存导出，当前没有导入恢复入口。
- **可访问性与响应式：** 检查桌面、390px 与 320px 宽度、键盘焦点、底栏遮挡及弹窗。WebGL 不可用时保留可用入口和文字信息；减少动态效果需区分源码支持与实际浏览器验证。

## 演示口径

> 我们帮助业主把生活需求整理成可追溯的版本，按房间保存，再让商家逐项回应。AI 用于需求整理、户型识别和发布后的关联分析；商家比对当前使用模拟数据与本地文字规则。最终决定由用户确认，现场条件和专业问题保留待核实。

本机保存不是云端协作；模型不是施工图；「已回应」不是验收通过。当前没有真实商家消息、报价交易或自动学习服务。

## 复现与证据

在 `mingma-lab` 执行 `npm test`、`npm run build`。可用 `npm run preview -- --port 5190` 检查静态构建；需要 AI 的完整流程使用有同源 API 转发的开发或本机部署入口。

[文档索引](README.md)列出各功能验证记录。浏览器辅助脚本会改写测试数据，不由 `npm test` 自动运行；只在脚本指定的独立测试环境执行。当前结果应记录实际命令、版本、模拟或真实服务、截图及未验证范围。
