# 风险评估栏目

澄境 `#assessment` 在需求形成后开放，作为独立辅助栏目；六步主流程仍按原方式解锁，已经取得的页面访问权限不会因风险而撤销。

## 操作

1. 完成需求共创，或从首页进入完整演示案例，打开导航中的“风险评估”。
2. 选择当前草稿、已发布需求版本或商家方案。八维列表可以筛选问题。
3. 查看问题原文，回到对应需求或商家工作区修改；也可内联记录资料、责任人及核实安排。
4. 处理记录不自动消除风险。源数据变化使旧评估失效，重新评估后更新当前结果。
5. 发布需求和确认选定方案都会再执行检查。需要业主处理的必须项冲突会阻断相关操作，现场或专业待办可随咨询继续保留。历史需求和方案不会被新评估改写。
6. 确认记录保留当时评估快照。可导出单份评估或包含评估历史的完整项目；刷新仍清空本轮数据。

## 实现

- `mingma-lab/shared/assessment.ts`：公开类型、八维定义、确定性规则、源数据签名与操作门槛。
- `mingma-lab/shared/assessment-ui.ts`、`assessment.css`：评估对象、结论、维度列表、问题详情、内联核实安排和历史展示。
- `mingma-lab/versions/lucid/src/main.ts`：状态、导航、目标选择、操作绑定、发布与选定时检查、快照和导出。
- `project-flow.ts`：需求形成后开放评估，保留原六步解锁行为。
- `assessment.test.ts`：缺失资料、必须项冲突、现场事项、版本失效、记录不能豁免风险、转义等边界。
- `scripts/browser-assessment.js`：独立测试浏览器中的本地合成演示回归，不调用模型、不修改真实项目。

每次评估保存规则版本、需求/方案标识、输入签名、八维结果、问题原文以及与当前来源匹配的处理记录。处理记录包含原问题的来源指纹，修改相关资料后旧记录不会被冒充为新证据。旧需求或已被新提交替代的方案仅供回看，不可据此选定当前方案。

## 规则边界

本版是咨询与协作检查，不是建筑鉴定。专业事项来自已记录待办，文本信号只生成待核实提示，不能推定承重性质或施工可行性。明确拒绝必须项、已记录的必须项决策冲突会阻断相关确认。

预算、预备金、结构化报价与必要工期未建立可靠输入口径，四个维度显示待评估；不计算价格、不伪造总分。FMEA 尚未有完整评分映射，因此不自动给出 RPN。当前专业安全信息缺失时同样显示待评估，不把“未识别问题”视作合格。

现有 `Finding` 继续表达文字回应程度；评估结果单独保存。责任安排不等于核实完成，当前没有专业人员认证、跨设备保存或真正施工确认入口。后续正式多人协作需要服务端持久化、权限控制及服务端确认校验。
